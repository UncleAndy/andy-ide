# ACP на официальном SDK: таблица соответствия

Замерено `crates/ide-agents/examples/acp_probe.rs` на нашей заглушке (`acp_test_agent`), 2026-11-01.
Проба запускает агента так же, как панель — командной строкой, — согласует версию протокола, открывает
сессию, шлёт одну реплику и печатает каждое уведомление и каждый запрос агента как есть.

```
cargo run -p ide-agents --example acp_probe -- "docker exec -i hermes-agent hermes acp" "скажи: проба"
```

## Что уже проверено вживую

- **Согласование версии и возможностей идёт.** Проба просит `ProtocolVersion::V1`, агент отвечает
  `protocolVersion: 1` и перечнем `agentCapabilities` (`loadSession: true` у заглушки). Это тот шаг,
  которого в нашем слое не было.
- **Что мы заявляем о себе** (из перехвата): `clientCapabilities = {fs: {readTextFile: false,
  writeTextFile: false}, terminal: false, auth: {terminal: false}}` — то же решение «файлы агент берёт
  сам, через терминал», но теперь оно часть согласования, а не наша договорённость с собой.
- **Исполнителя SDK не приносит.** Крейт не зависит от tokio; его собственные проверки гоняют соединение
  через `futures::executor::block_on`, и наш поток агента может делать то же — синхронный `Session`
  ложится на SDK без асинхронного движка в проекте.
- **`id` — непрозрачен.** Стандарт разрешает и число, и строку; SDK шлёт UUID. Наш слой и заглушка знали
  только числа: первая проба зависла на `initialize`, потому что заглушка приняла строковый `id` за
  отсутствующий (уведомление) и промолчала. Заглушка исправлена (id переносится как есть).

## Таблица

| Наше (`ide_agents::Event`) | Стандарт, `schema::v1` | Состояние |
|---|---|---|
| `Setup(SessionState)` | `InitializeResponse` (capabilities) + `NewSessionResponse` | есть, но собирается из нескольких мест |
| `Commands(Vec<AgentCommand>)` | `SessionUpdate::AvailableCommandsUpdate` | есть · проверено |
| текст агента | `SessionUpdate::AgentMessageChunk` (ContentChunk) | есть · проверено |
| `Thinking` | `SessionUpdate::AgentThoughtChunk` | есть |
| слова человека (при восстановлении) | `SessionUpdate::UserMessageChunk` | есть |
| `Tool`, `Plan` | `ToolCall`, `ToolCallUpdate`, `Plan` | есть |
| `Usage { used, size }` | `SessionUpdate::UsageUpdate { used, size }` | есть · проверено |
| `Choice { id, request }` (форма с вариантами) | `elicitation/create` → `CreateElicitationRequest` (`mode: form`, `oneOf: [{const,title}]`), ответ `ElicitationAction` | есть · проверено кругом |
| `Permission { id, request }` | `session/request_permission` → `RequestPermissionRequest { tool_call, options: [{optionId, name, kind}] }` | есть в схеме, пробой ещё не гоняли |
| `Sessions(Vec<SessionInfo>)` | `session/list` (`SessionCapabilities.list`) | есть |
| `Finished(reason)` | `PromptResponse.stop_reason` (`EndTurn`, `Cancelled`, …) | есть · проверено |
| `Closed` | закрытие транспорта (EOF) | есть |
| `Failed(String)` | `Error` (JSON-RPC) внутри `schema::v1::Error` | есть |
| `Other { kind }` | любой `SessionUpdate`, которого панель не показывает | есть (в схеме `#[non_exhaustive]`) |
| — (у нас распознаём по тексту) | `SessionUpdate::Notice`, `CompactionUpdate`, `CompactionSummaryChunk` | **есть в стандарте, но Hermes их не шлёт** (`acp_adapter/*` их не собирает) — распознавание по форме остаётся |
| — | `fs/read_text_file`, `fs/write_text_file`, `terminal/*` | агент может спросить; мы заявляем `false`, и SDK на необработанный запрос отвечает отказом |
| — | `_meta` (произвольные поля, напр. `sessionProvenance`) | едет как есть, типизировано как `Meta` |

## Что из этого следует для перевода

1. **Поверхность `Session` сохраняется** (`start_with`, `next_event`, `answer_permission`, `answer_choice`,
   `list_sessions`, `cancel`, `set_model`, `set_mode`, `set_option`, `begin`, `load_into`), и на SDK
   ложится её нутро, а не панель: `crates/andy-ide` не меняется.
2. **Журнал провода сохраняется** — иначе теряется единственное, что отличает «агент молчал» от «панель не
   нарисовала». Схема предлагает для этого свои транспорты (`Lines`, `BytesStreams`, `Channel`), значит
   обёртка вокруг чтения/записи остаётся возможной.
3. **`docs` в `_meta` и `Notice`/`Compaction*`** — то, что стоит начать читать стандартно, но с оговоркой:
   наш агент их не шлёт, поэтому распознавание сводки по тексту убирать нельзя.


## Замер на настоящем Hermes (`hermes-agent 0.22.5`, 2026-11-01)

Одна реплика, полный протокол, 11 строк вывода:

- `initialize` → `protocolVersion: 1`, `agentInfo: hermes-agent 0.22.5`,
  `loadSession: true`, `promptCapabilities: {image: true}`,
  `sessionCapabilities: {list, resume}` — то есть **и список разговоров, и продолжение разговора в
  стандарте есть**, и наш слой их уже использует (`session/list`, `session/load`).
- `authMethods`: `nous` (credentials) и `hermes-setup` (`--setup`) — панель их никак не показывает.
- `available_commands_update` — 14 команд, с `input.hint` у тех, что просят довод.
- **`session_info_update` с заголовком разговора** — и агент переписывает его по ходу («Ответь одним
  словом: проба» → «Проба»). У нас для этого свой склад (`session_names`) и своя кнопка переименования;
  стандарт предлагает и то, и другое на проводе.
- `agent_message_chunk` несёт `messageId` — поля, которого наш разбор не знает.
- `usage_update {used: 25948, size: 1048576}` — настоящие числа контекста.
- `PromptResponse.stop_reason: EndTurn`.

Чего в коротком ходе не было: `_meta.sessionProvenance` (приходит со сжатием), `Notice`,
`CompactionUpdate`. Поэтому распознавание сводки по форме текста остаётся до отдельного замера на сжатии.

## Остаток поверхности и два сырых ответа (2026-11-01, вторая часть)

Дозволение, форма выбора, `session/list`, `session/cancel`, `session/set_mode`, `session/set_config_option`,
`session/new` и `session/load` переведены на SDK (`crates/ide-agents/src/acp.rs`) и закрыты проверками
`crates/ide-agents/tests/sdk_session.rs`. Что нашлось по пути:

- **Запрос дозволения отвечается «отвечающим» SDK** (`Responder<RequestPermissionResponse>`), который лежит в
  карте по нашему номеру вопроса: ответ человека приходит из другого потока и сколько угодно позже. Проверено
  кругом: `ask` → «allowed», `choose` → выбранный вариант.
- **Цикл приказов не должен ждать ход.** Первая версия ждала `PromptRequest` прямо в цикле, а ответ человека
  приходит *во время* хода — это и есть смысл запроса дозволения, — и обе новые проверки падали по сроку.
  Теперь ход уходит задачей (`cx.spawn`), ходы друг за другом держит `futures::lock::Mutex`, а цикл свободен
  для ответов. То же место понадобится `cancel`: `session/cancel` отправляется во время хода.
- **`session/set_model` в схеме 1.13.0 нет вовсе**, а `models` в `NewSessionResponse`/`LoadSessionResponse`
  хранить негде. Между тем настоящий Hermes шлёт именно `models`:

  ```json
  {"sessionId":"local-968b…","modes":{"currentModeId":"default","availableModes":[…]},
   "models":{"currentModelId":"nous:anthropic/claude-fable-5.1","availableModels":[…]}}
  ```

  Типизированный запрос это поле **отбрасывает**, и меню моделей панели пустеет — потеря не от стандарта, а
  от разницы в написании. Поэтому ответы на `session/new` и `session/load` читаются сырыми
  (`NewSessionRaw`/`LoadSessionRaw`, `response = serde_json::Value`) и разбираются прежними разборщиками
  (`session_state`). Контроль: вернуть типизированный запрос — проверка
  `the_model_menu_of_an_agent_that_names_its_models_hermes_way_still_arrives` падает («the model menu was
  lost to a field the schema does not know: []»).
- **Меню моделей берётся из двух источников** (`fill_models`): сначала `models` агента, если он их шлёт,
  иначе — выборы настройки с `category: "model"` (так модель несёт стандарт). Обе дороги закрыты проверками
  (`--no-models --model-as-setting` у заглушки против её же поведения по умолчанию).
- **Заглушка научена обоим написаниям**: по умолчанию — как Hermes (поле `models`, настройки модели нет),
  с `--model-as-setting` — по стандарту (настройка `model`, поля `models` нет), с `--no-models` — без поля.

Что из прежних открытых вопросов закрыто:

- ~~дозволение~~ — сделано и проверено кругом;
- ~~`session/set_model`~~ — выяснено: в стандарте такого метода нет. С Hermes 0.22.5 смена модели
  **стандартного пути не имеет** (ни настройки `model`, ни метода), и панель честно сообщает, что сменить
  нельзя, вместо показа изменения, которого не было. Это единственная потерянная возможность, и лечится она
  на стороне агента — настройкой `model` в `configOptions` (Hermes не правим без разрешения);
- **`fs`/`terminal`** — обработчиков у нас по-прежнему нет (заявляем `false`), и Hermes за целый ход не
  спросил ничего. Поведение SDK на запрос без обработчика так и не замерено.

## Файлы и терминал: запрос без ответа — это ход без конца (2026-11-01, третья часть)

Замерено разовой пробой на заглушке (`read` — она просит `fs/read_text_file`): **SDK не отвечает за
клиента**. У него есть ветка «нет обработчика → `Method not found`», но она не достаёт запросов, типы
которых он знает: запрос агента остался без ответа, и ход не кончился — ни текста, ни `stopReason` за 30
секунд. Это худший вид отказа: молчание, неотличимое от работы.

Поэтому обработчики поставлены на все семь запросов, которые агент может задать клиенту:

| Запрос агента | Что отвечает панель |
| --- | --- |
| `fs/read_text_file` | читает файл **в пределах проекта** (`inside_project`: `..` и пути вне корня → `InvalidParams`); нет файла — `InternalError` |
| `fs/write_text_file` | пишет только если панель согласилась (`Session::allow_writes`, иначе `MethodNotFound`); путь проверяется так же |
| `terminal/create`, `terminal/output`, `terminal/wait_for_exit`, `terminal/kill`, `terminal/release` | `MethodNotFound` с объяснением: своего терминала панель не даёт, у агента свой |

`allow_writes` — часть прежней поверхности и остался (`conversation.rs` им пользуется); правила границы
проекта перенесены из прежнего слоя дословно. Проверки — четыре, у каждой свой контроль: снять
обслуживание чтения → падает «файл не подан»; снять границу → падает «файл вне проекта подан»; снять
согласие на запись → падает «запись прошла без согласия».

## Откат на агентский метод: правила (2026-11-01, решено с Andy)

Смена модели у Hermes 0.22.5 остаётся работающей, но через **его собственный метод** `session/set_model`,
которого в стандарте нет. Решено так:

1. **Стандартная дорога первая.** Если агент предлагает настройку с `category: "model"` — смена идёт
   `session/set_config_option`, и откат не вызывается.
2. **Откат — только когда стандартной дороги нет**: настройки `model` нет, но агент назвал свои модели
   (поле `models`). Тогда идёт сырой `SetModelRaw` (`session/set_model`, `{sessionId, modelId}`).
3. **Откат себя выдаёт.** Каждый его вызов пишется в журнал провода строкой-пометкой: «модель меняется
   собственным методом агента (session/set_model), потому что настройки для неё он не предлагает». В журнале
   рядом видно и саму строку запроса, так что «чьим путём пошло» читается и глазами, и по проводу.
4. **Откат отмирает сам.** В день, когда Hermes начнёт отдавать модель настройкой, `set_model` пойдёт
   стандартной дорогой, а откат перестанет вызываться — без правок и без флагов.
5. **Попытка с честной ошибкой.** Форма агентского метода тоже не стандарт: если он перестанет отвечать,
   панель скажет, что сменить не удалось, и не покажет изменение как сделанное. Если у агента нет ни
   настройки, ни своих моделей — панель просто сообщает, что сменить нельзя.

Проверки (в `sdk_session.rs`, всего 16):

- `the_standard_road_is_taken_when_the_agent_offers_both` — заглушка предлагает и то, и другое; проверяется,
  что пошла **стандартная** дорога (настройка, прочитанная агентом обратно, изменилась; откат её не трогает).
  Контроль: поставить откат вперёд — падает.
- `the_way_back_is_written_into_the_record` — в журнале есть пометка отката и строка запроса `session/set_model`.
  Контроль: снять пометку — падает словами «без слова об этом в журнале».
- `the_model_menu_of_an_agent_that_names_its_models_hermes_way_still_arrives` — с таким агентом смена
  проходит и агент подтверждает её своим словом (`large / ask`).

## Шаг 3: подмена за поверхностью `Session` (2026-11-01)

`crates/ide-agents/src/session.rs` больше не содержит своей реализации протокола: там остались слова
поверхности (`Event`, `AgentSpec`, `PermissionPolicy`, `HELLO`, `ANSWER`) и `pub use crate::acp::Session` —
сама сессия живёт в `acp.rs` и говорит через SDK. **`crates/andy-ide` не изменился ни на строку по этой
причине**: панель собирается как прежде.

Приёмка — `crates/ide-agents/tests/conversation.rs` (21 проверка, все зелёные) и панельные проверки; она и
вскрыла, чего поверхность требует, а новая реализация не делала:

- **`prompt` не должен съедать события.** Он ждёт конца хода, а куски ответа приходят *до* него: старый слой
  оставлял их в очереди, мой первый вариант выбрасывал — и «ответ» после `prompt` читался пустым. Теперь
  отложенное возвращается в очередь в исходном порядке.
- **Слова отказа — слова поверхности**: «the agent did not answer» (срок) и «the agent closed its output»
  (процесс умер). Второе SDK называет своим устойчивым признаком
  (`agent_client_protocol::is_incoming_transport_closed`) — по тексту сообщения ничего не угадывается.
- **Забытая беседа открывается заново.** `session/load` с id, которого агент не знает, — не ошибка для
  панели: человек хотел разговор здесь. Теперь открывается новая беседа, и `resumed` честно говорит `false`.
- **Шаги запуска — прежние слова**: `Launching…`, `Getting agent parameters…`, `Getting model parameters…`
  (последний — тот, на котором приходят модели).
- **Обещания окна о себе сохранены**: в рукопожатии `clientCapabilities` с `readTextFile: false`,
  `writeTextFile: false`, `terminal: false`, а рядом с каталогом — прежняя заметка `_meta`
  (`client`, `fileAccess: "terminal"`, текст про терминал).
- **Смерть процесса замечается зорким.** Транспорт, увидевший EOF, сам по себе не кончает задачу сессии: она
  ждала приказа и продолжала ждать, а панель не узнавала о падении (проверка
  `gui_tests::the_agent_panel::a_crashed_agent_is_started_again_with_the_conversation_restored` это и
  поймала). Теперь рядом живёт маленький сторож, который смотрит на процесс и кончает задачу, когда его нет.
- **Панель перестала заявлять «resumed» вслепую**: после перехода на беседу, которой агент не помнит,
  панель спрашивает у сессии, а не предполагает.

Что осталось на потом: в `protocol.rs` лежат ещё мёртвые формы прежнего своего провода (сборщики доводов,
`Message`, `Update`, ответы на вопросы) — их предстоит убрать вместе с их проверками.

## Остатки прежнего протокола убраны (2026-11-01)

`protocol.rs` был 1505 строк: рядом с живыми разборщиками лежали мёртвые формы прежнего своего провода —
`Message`, `Update` с его разбором, сборщики доводов (`*_params`), ответы на вопросы (`permission_answer`,
`choice_answer`), счётчики контекста `usage_of`/`usage_update_of`, старые возможности клиента. Всё это теперь
делает SDK, а мёртвые формы — только повод разойтись с ним. Убрано 22 объявления (с их `impl` и проверками),
осталось 990 строк: разборы ответов агента (`session_state`, `options_of`, `sessions_of`), вопросы
(`PermissionRequest`, `ChoiceRequest`), слова панели (`Event`, `AgentCommand`, `SessionState`, `Usage`,
`Model`, `Mode`, `ConfigOption`) и `first_line`.

Проверки `protocol.rs` (27 вместо 41) держат теперь только то, что живо: как читаются настройки Hermes,
ответ сессии, вопросы с вариантами и без, и что ответ без вариантов — это отказ. Три правила, которые
раньше стерегли удалённые проверки, перенесены туда, где они идут по-настоящему (`sdk_session.rs`): вопрос
со свободным ответом, вопрос с несколькими ответами и отказ человека (агент слышит «refused», а не вариант).
