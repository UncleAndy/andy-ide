# Техническое задание: andy-ide

Версия документа: 0.1

## 1. Общие сведения

**Предмет.** Настольная интегрированная среда разработки (IDE) класса JetBrains, написанная на Rust. Рабочее название — `andy-ide`.

**Назначение.** Среда для разработки программ и для работы с ИИ-агентами в одном окне: код, навигация по нему, терминал, система контроля версий и диалог с агентом находятся рядом и используют общий контекст проекта.

**Исходная база.** Проект создаётся с нуля в каталоге `~/projects/RUST/andy-ide`. Готового кода нет; каталог `docs/` пуст.

**Стек.**

| Слой | Технология | Версия |
|---|---|---|
| Язык | Rust, edition 2024 | toolchain ≥ 1.95 |
| Графический интерфейс | `egui` / `eframe` | 0.36.2 |
| Док-панели | `egui_dock` | 0.21.1 |
| Текстовый буфер | `ropey` | 1.6.1 |
| Подсветка и структура кода | `tree-sitter` + грамматики языков | 0.27.1 |
| Семантическая навигация | LSP-клиент (`lsp-types` 0.97, `async-lsp` 0.2.4) | — |
| Агенты | ACP (`agent-client-protocol` 3.5), MCP (`rmcp` 3.8) | — |
| Терминал | `portable-pty` 0.9, `vt100` 0.18 | — |
| Git | `gix` 0.90, системный `git` для сетевых операций | — |
| Асинхронность | `tokio` 1.54 | — |
| Сборка окружения | Nix flake, `nixos-26.05` | — |

**Лицензия.** Двойная: MIT OR Apache-2.0.

**Платформа.** Первичная — Linux (NixOS 26.05), графическое окружение Wayland/X11. Переносимость на macOS и Windows закладывается архитектурно, но не входит в объём первой версии.

## 2. Цели и задачи

**Цели.**

1. Дать рабочую среду, в которой разработка и общение с ИИ-агентом происходят в одном окне и над одним проектом.
2. Обеспечить навигацию по коду не хуже, чем у зрелых IDE, за счёт использования языковых серверов (LSP), а не собственного анализатора.
3. Сделать подключение агентов расширяемым: Hermes — первый, но не единственный.

**Задачи.**

1. Реализовать интерфейс управления проектами.
2. Реализовать интерфейс работы с файлами: дерево, вкладки, редактирование, сохранение.
3. Реализовать подсветку синтаксиса для набора языков средствами tree-sitter.
4. Реализовать навигацию по коду через LSP.
5. Реализовать встроенную работу с агентами через протокол ACP, начиная с Hermes.
6. Реализовать встроенный терминал на реальном PTY.
7. Реализовать работу с Git: состояние, диффы, индексирование, коммиты, ветки.

**Не-цели (вне объёма первой версии).**

- Совместное редактирование в реальном времени.
- Собственный компилятор, отладчик и профилировщик.
- Мобильные и веб-версии.
- Собственная реализация языкового анализа: семантика берётся у LSP-серверов.
- Плагины сторонних авторов с изоляцией и собственным API-контрактом.

**Анти-цели (что означает провал, даже если программа работает).**

- Тормозящий ввод: задержка между нажатием клавиши и появлением символа больше 16 мс на файле в 10 000 строк.
- Подсветка, требующая полного перепарсивания файла на каждое нажатие.
- Блокировка интерфейса на время запуска языкового сервера, git-операции или ответа агента.
- Привязка ядра к конкретному GUI: смена графической библиотеки не должна требовать переписывания навигации, git, терминала или агентов.

## 3. Функциональные требования

### 3.1. Работа с проектами

**Модель.** Проект — это каталог на диске плюс файл настроек `.andy-ide/project.toml` внутри него. Проект может быть открыт и без файла настроек: тогда действуют настройки по умолчанию.

**Требования.**

1. Открытие проекта: выбор каталога через диалог, открытие последнего проекта при старте, переключение между недавними проектами.
2. Список недавних проектов хранится в `~/.config/andy-ide/recent.json`, максимум 20 записей, самая свежая — первой.
3. Дерево проекта: иерархия каталогов и файлов, ленивая загрузка содержимого каталога при раскрытии.
4. Уважение к правилам исключений: содержимое `.gitignore` и скрытые файлы, начинающиеся с точки, по умолчанию не показываются; переключатель «показывать скрытые» есть в настройках панели.
5. Автоматическое обновление дерева при изменении файлов на диске (внешнее создание, удаление, переименование) без ручного обновления.
6. Поиск файла по имени во всём проекте (fuzzy), открывается по `Ctrl+P`.
7. Переименование, создание и удаление файлов и каталогов из дерева, с подтверждением на удаление.

**Критерий приёмки.** После открытия каталога дерево показывает его структуру; созданный извне файл появляется в дереве в течение одной секунды; `Ctrl+P` находит файл по частичному совпадению имени.

### 3.2. Работа с файлами

**Требования.**

1. Открытие файла двойным щелчком в дереве, из quick-open, из перехода по определению.
2. Вкладки: заголовок с именем файла, отметка несохранённых изменений, закрытие по средней кнопке мыши и по `Ctrl+W`, переключение `Ctrl+Tab`.
3. Разделение области редактирования на две группы (горизонтально или вертикально), перенос вкладки между группами.
4. Редактирование: ввод, удаление, выделение мышью и клавиатурой, копирование/вставка/вырезание, отмена и повтор (не менее 1000 шагов истории на документ).
5. Отступы: ширина по языку (по умолчанию 4 пробела), автоотступ по предыдущей строке, Tab/Shift+Tab для выделенного блока.
6. Номера строк, текущая строка подсвечена, позиция курсора (строка:столбец) видна в строке состояния.
7. Поиск и замена внутри файла (`Ctrl+F`, `Ctrl+H`) с подсветкой совпадений и переходом между ними.
8. Сохранение `Ctrl+S`; сохранение всех вкладок `Ctrl+Shift+S`. Запись выполняется атомарно: во временный файл в том же каталоге с последующим переименованием.
9. Обнаружение внешнего изменения открытого файла: если файл изменён на диске и в редакторе нет несохранённых правок, содержимое перечитывается; если правки есть — выводится запрос на выбор.
10. Восстановление сессии: при следующем запуске открываются вкладки и позиции курсоров предыдущей сессии.

**Критерий приёмки.** Файл в 10 000 строк открывается и редактируется без заметной задержки ввода; закрытие вкладки с правками требует подтверждения; после перезапуска вкладки и курсоры восстанавливаются.

### 3.3. Подсветка синтаксиса

**Механизм.** Подсветка выполняется tree-sitter: для каждого языка подключается грамматика и набор highlight-запросов. Парсинг инкрементальный: при правке перепарсивается только изменённый участок дерева, поэтому стоимость правки не зависит от размера файла.

**Поддерживаемые языки первой версии.**

| Язык | Грамматика | Дополнительно |
|---|---|---|
| Rust | `tree-sitter-rust` 0.24 | — |
| Python | `tree-sitter-python` 0.25 | — |
| TypeScript / JavaScript / TSX | `tree-sitter-typescript` 0.23 | три варианта грамматики |
| JSON | `tree-sitter-json` 0.24 | — |
| TOML | `tree-sitter-toml-ng` 0.7 | — |
| Markdown | `tree-sitter-md` 0.5 | предпросмотр отрендеренного документа |
| Bash | `tree-sitter-bash` 0.25 | — |
| Go | `tree-sitter-go` 0.25 | — |
| C / C++ | `tree-sitter-c` 0.24, `tree-sitter-cpp` 0.23 | — |

**Требования.**

1. Язык файла определяется по расширению; для файлов без расширения — по первой строке (shebang) и по имени (`Makefile`, `Dockerfile`).
2. Цветовые схемы: тёмная (по умолчанию) и светлая, переключение в настройках; цвета задаются в одном месте и применяются ко всем языкам.
3. Набор классов токенов, который обязана различать подсветка: ключевое слово, тип, функция, метод, переменная, константа, строка, escape-последовательность в строке, число, комментарий, документационный комментарий, атрибут/аннотация, оператор, пунктуация, неверный синтаксис.
4. Неверный синтаксис подсвечивается подчёркиванием, но не ломает подсветку остального файла.
5. Подсветка работает без языкового сервера: открытие файла не требует запуска внешних процессов.
6. Для Markdown доступен предпросмотр (клавиша `Ctrl+Shift+V` или кнопка на панели вкладки): заголовки, списки, таблицы, блоки кода с подсветкой, ссылки, выделение. Предпросмотр обновляется при правке с задержкой не более 300 мс.

**Критерий приёмки.** Каждый из девяти языков открывается с корректной подсветкой на подготовленном образце; вставка 1000 строк в середину файла в 10 000 строк не вызывает заметного мигания и не перепарсивает файл целиком.

### 3.4. Навигация по коду

**Механизм.** Навигация выполняется языковыми серверами по протоколу LSP. Среда выступает клиентом: запускает сервер для языка проекта, передаёт изменения документа, получает ответы. Собственного анализатора кода нет.

**Серверы по умолчанию.**

| Язык | Сервер | Команда |
|---|---|---|
| Rust | rust-analyzer | `rust-analyzer` |
| Python | Pyright | `pyright-langserver --stdio` |
| TypeScript / JavaScript | tsserver (`typescript-language-server --stdio`) | — |
| C / C++ | clangd | `clangd` |
| Go | gopls | `gopls` |
| TOML | taplo | `taplo lsp stdio` |

Список серверов расширяется файлом `.andy-ide/lsp.toml`: язык, команда, аргументы, корневые маркеры проекта.

**Обязательные операции.**

1. **Переход к определению** — `textDocument/definition`, по `Ctrl+Click` и `F12`; если целей несколько — список выбора, если одна — переход.
2. **Поиск мест использования** — `textDocument/references`, `Shift+F12`; результат в панели со списком «файл : строка : фрагмент», переход по щелчку.
3. **Поиск реализаций** — `textDocument/implementation`, `Ctrl+F12`; для метода интерфейса или типа показывает реализации.
4. **Иерархия вызовов** — `textDocument/prepareCallHierarchy` и `callHierarchy/incomingCalls`: список мест, откуда вызывается указанный метод.
5. **Символы файла** — `textDocument/documentSymbol`, панель структуры (`Ctrl+F12` в панели структуры), переход по щелчку.
6. **Символы проекта** — `workspace/symbol`, поиск по имени символа (`Ctrl+Shift+O`).
7. **Переход к типу** — `textDocument/typeDefinition`.
8. **Наведение** — `textDocument/hover`: тип выражения и документация во всплывающей подсказке.
9. **Переименование** — `textDocument/rename`, `Shift+F6`, с предварительным показом списка изменений и подтверждением.
10. **Диагностика** — `textDocument/publishDiagnostics`: ошибки и предупреждения в панели проблем, отметки в полосе прокрутки, подчёркивание в тексте.
11. **Автодополнение** — `textDocument/completion`, список с фильтрацией по введённому префиксу; вставка учитывает `textEdit` сервера.

**Требования к устойчивости.**

1. Запуск сервера не блокирует интерфейс; до готовности сервера навигационные команды показывают состояние «сервер запускается».
2. Падение или отсутствие сервера не влияет на редактирование, подсветку, терминал и git.
3. Файл без сервера: переход к определению и поиск ссылок работают в режиме «поиск по тексту» (совпадение имени символа), с явной пометкой, что результат текстовый.
4. Перезапуск сервера по команде из панели состояния.

**Критерий приёмки.** На проекте на Rust: `Ctrl+Click` по вызову функции переходит в её объявление; `Shift+F12` на методе возвращает все места вызова, включая вызовы через трейт; для типа, реализующего трейт, `Ctrl+F12` показывает реализации; навигация работает до завершения фоновой индексации проекта без падения интерфейса.

### 3.5. Работа с ИИ-агентами

**Механизм.** Агент подключается как внешний процесс по протоколу ACP (Agent Client Protocol) — тому же, которым пользуется редактор Zed для подключения Claude Code, Gemini CLI и подобных. Дополнительно поддерживается MCP как источник инструментов и данных для агента. Ядро среды не зависит от конкретного агента: агент описывается записью в конфигурации.

**Модель.**

1. Агент — это запись: имя, команда запуска, аргументы, набор передаваемых возможностей (файловая система, терминал).
2. Реестр агентов хранится в `~/.config/andy-ide/agents.toml`. Первым поставляется адаптер Hermes.
3. Одновременно может быть активно несколько сессий агента, каждая — со своей панелью.

**Требования.**

1. Панель агента: диалог (сообщения пользователя и агента), поле ввода, список сессий, кнопка остановки текущего ответа.
2. Агент видит проект: получает корень проекта, открытые файлы и выделенный фрагмент как контекст запроса.
3. Агент может предложить правку файла. Предложенная правка показывается как дифф в редакторе, применяется только после подтверждения пользователем; есть «принять», «отклонить», «принять всё».
4. Агент может запросить разрешение на выполнение команды в терминале; запрос показывается в панели агента с текстом команды, разрешение выдаётся на одну команду или на сессию.
5. Потоковый вывод: текст ответа появляется по мере генерации, а не после завершения.
6. История сессий сохраняется на диске и переживает перезапуск среды.
7. Отключение или падение агента не влияет на остальные функции: панель показывает ошибку и кнопку перезапуска.

**Критерий приёмки.** В панели агента Hermes отвечает на вопрос о содержимом открытого файла, ссылаясь на реальный код; предложенная правка отображается диффом и не применяется без подтверждения; разрешение на команду запрашивается явно.

### 3.6. Терминал

**Механизм.** Настоящий псевдотерминал (PTY) через `portable-pty`, эмуляция экрана через `vt100`. Среда не эмулирует оболочку и не ограничивает запускаемые программы.

**Требования.**

1. Несколько сессий терминала, каждая — вкладка панели; создание (`Ctrl+Shift+T`), закрытие, переключение.
2. Полноценный интерактивный терминал: цвета (16 и 256 цветов), курсор, прокрутка истории, изменение размера окна передаётся в PTY.
3. Поддержка полноэкранных консольных программ: `vim`, `htop`, `less`, `tmux`.
4. Копирование и вставка: выделение мышью, `Ctrl+Shift+C` / `Ctrl+Shift+V`.
5. Рабочий каталог новой сессии — корень проекта; текущий каталог отображается в заголовке вкладки.
6. Ссылки в выводе распознаются и открываются по `Ctrl+Click` (файл:строка — в редакторе, URL — в браузере).
7. Терминал продолжает работать при переключении вкладок проекта; закрытие среды завершает дочерние процессы.

**Критерий приёмки.** В панели терминала запускается `htop`, отображается корректно, реагирует на изменение размера панели; `vim` открывает и сохраняет файл; вывод с цветами отображается цветным.

### 3.7. Работа с Git

**Механизм.** Чтение состояния репозитория, история и диффы — нативно через `gix`. Операции, требующие аутентификации и сетевого взаимодействия (`fetch`, `pull`, `push`), выполняются вызовом системного `git`, чтобы не реализовывать работу с ключами, токенами и прокси самостоятельно.

**Требования.**

1. Определение репозитория: при открытии проекта среда находит корень репозитория и текущую ветку.
2. Панель Git: изменённые, новые и удалённые файлы; индексированные и неиндексированные изменения разделены.
3. Дифф: открывается в области редактирования в режиме только для чтения, с подсветкой добавленных и удалённых строк; для каждого файла и для всего набора.
4. Индексирование и снятие с индексации отдельного файла и всех файлов; коммит с сообщением; отмена последнего коммита (`soft reset`).
5. Ветки: список локальных и удалённых, создание, переключение; переключение при несохранённых изменениях требует подтверждения.
6. История коммитов: список с автором, датой и сообщением; дифф выбранного коммита.
7. Отметки в редакторе: изменённые относительно индексации строки отмечаются на левом поле; при наведении — автор последнего изменения строки (blame).
8. Сетевые операции: `fetch`, `pull`, `push` — с выводом прогресса и текста ошибки системного `git` без потери информации.
9. Работа вне репозитория: панель Git показывает состояние «проект не является репозиторием» и предлагает инициализацию.

**Критерий приёмки.** Изменённый файл появляется в панели Git, дифф открывается с корректной подсветкой строк, коммит создаётся и виден в истории; переключение ветки с несохранёнными правками требует подтверждения; `push` в недоступный удалённый репозиторий показывает реальную ошибку `git`.

## 4. Архитектура и компоненты

### 4.1. Разделение на крейты

Проект — рабочее пространство Cargo. Всё, кроме `andy-ide`, — библиотечные крейты без зависимости от `egui`: это гарантирует, что смена графической библиотеки не потребует переписывания логики.

| Крейт | Ответственность | Зависит от |
|---|---|---|
| `ide-core` | модель проекта, дерево файлов, конфигурация, сессии, наблюдатель файловой системы | `serde`, `toml`, `notify`, `ignore` |
| `ide-syntax` | реестр языков, грамматики tree-sitter, вычисление раскраски, инкрементальный парс | `tree-sitter`, грамматики |
| `ide-buffer` | текстовый буфер на `ropey`, курсоры, выделения, история отмен | `ropey` |
| `ide-lsp` | клиент LSP, реестр серверов, синхронизация документа, типизированные запросы | `lsp-types`, `async-lsp`, `tokio` |
| `ide-agents` | реестр агентов, клиент ACP, мост MCP, модель сессии и правок | `agent-client-protocol`, `rmcp`, `tokio` |
| `ide-term` | PTY-сессии, эмуляция экрана, буфер вывода, распознавание ссылок | `portable-pty`, `vt100` |
| `ide-git` | состояние репозитория, диффы, индекс, коммиты, ветки, история, blame | `gix`, `tokio` |
| `andy-ide` | графический интерфейс: окно, док-панели, редактор, панели проектов, агента, терминала, git | все перечисленные, `eframe`, `egui_dock` |

### 4.2. Потоки исполнения

1. **Поток интерфейса** — единственный, владеет состоянием `egui` и отрисовкой. Никакая операция ввода-вывода в нём не выполняется синхронно дольше 1 мс.
2. **Рантайм `tokio`** — фоновые задачи: запуск и обмен с языковыми серверами, агентами, git-операции, чтение файлов.
3. **Потоки чтения PTY** — по одному на сессию терминала, передают байты в канал.
4. **Связь** — каналы `crossbeam-channel`/`std::sync::mpsc`: фон отправляет события, поток интерфейса их разбирает в начале кадра и запрашивает перерисовку.

### 4.3. Поток данных: правка текста

```
клавиша → ide-buffer: правка дерева (ropey) → ide-syntax: инкрементальный parse + highlight
        → andy-ide: раскраска видимого диапазона → отрисовка
        → (с задержкой) ide-lsp: textDocument/didChange
```

Требование: раскраска вычисляется только для видимых строк плюс запас в 100 строк; полный список диапазонов токенов хранится в кэше и сбрасывается только для изменённых участков.

### 4.4. Поток данных: навигация

```
F12 / Ctrl+Click → ide-lsp: textDocument/definition → список Location
                 → ide-core: открыть файл, позиционировать курсор
```

Каждый запрос имеет идентификатор и срок жизни: ответ на устаревший запрос (пользователь уже сменил позицию) отбрасывается.

### 4.5. Поток данных: агент

```
пользователь → ide-agents: prompt (текст + контекст: корень, файл, выделение)
             → ACP: session/prompt → поток session/update (текст, инструменты, правки)
             → andy-ide: панель агента, дифф правки, запрос разрешения
подтверждение → ide-buffer: применить правку → сохранение
```

### 4.6. Конфигурация

| Файл | Назначение |
|---|---|
| `~/.config/andy-ide/config.toml` | общие настройки: тема, шрифт, размер, отступы, показ скрытых файлов |
| `~/.config/andy-ide/agents.toml` | реестр агентов |
| `~/.config/andy-ide/recent.json` | недавние проекты |
| `~/.config/andy-ide/session.json` | открытые вкладки, позиции курсоров, раскладка панелей |
| `<проект>/.andy-ide/project.toml` | настройки проекта: языки, исключения, отступы |
| `<проект>/.andy-ide/lsp.toml` | переопределение списка языковых серверов |

Формат настроек — TOML; отсутствие файла не является ошибкой; неизвестные ключи сохраняются при перезаписи и не вызывают отказа.

## 5. Технические требования

1. **Язык и стиль.** Rust, edition 2024. Сборка без предупреждений: `cargo clippy --all-targets -- -D warnings`, форматирование `cargo fmt --check`.
2. **Ошибки.** Библиотечные крейты возвращают типизированные ошибки (`thiserror`), прикладной код — `anyhow`. `unwrap`/`expect` в библиотеках запрещены, кроме случаев, доказуемо невозможных, с комментарием.
3. **Асинхронность.** Все внешние взаимодействия — асинхронные, с таймаутами: запуск языкового сервера 30 с, запрос навигации 10 с, ответ агента без ограничения (но с возможностью отмены).
4. **Логи.** `tracing`, вывод в файл `~/.local/state/andy-ide/andy-ide.log` с ротацией по 10 МБ, уровень по переменной `ANDY_IDE_LOG`.
5. **Тесты.** Модульные тесты на каждую единицу логики в библиотечных крейтах; интеграционные тесты на разбор файлов всех поддерживаемых языков, на диффы git (на временном репозитории), на PTY-сессию, на протокол агента (заглушка вместо процесса). Доля кода, покрытого тестами, в библиотечных крейтах — не ниже 60 %.
6. **Производительность.** Открытие файла 10 000 строк — до 200 мс; ввод символа — до 16 мс; поиск файла по имени в проекте из 50 000 файлов — до 300 мс после прогрева индекса.
7. **Память.** Открытый файл в 1 МБ не должен занимать больше 5 МБ оперативной памяти с учётом дерева разбора и кэша подсветки.
8. **Сборка.** `nix develop` даёт готовое окружение: rustc, cargo, clippy, rustfmt, rust-analyzer, языковые серверы, `git`, `pkg-config`, библиотеки X11/Wayland для `eframe`. Артефакты сборки выносятся за пределы репозитория через `CARGO_TARGET_DIR`.
9. **Запуск.** `cargo run -p andy-ide` открывает окно; параметр `--project <путь>` открывает указанный каталог; параметр `--file <путь>` открывает файл.
10. **Кроссплатформенность.** Код, зависящий от платформы (PTY, пути конфигурации), изолируется в отдельные модули за общим интерфейсом.

## 6. Этапы разработки

Этапы идут последовательно; каждый заканчивается работающей программой и собственным набором тестов.

**М1. Каркас и редактирование.**
Окно, док-панели, дерево проекта, вкладки, текстовый буфер, подсветка tree-sitter для девяти языков, сохранение файла, предпросмотр Markdown, quick-open, восстановление сессии. Навигация, терминал и git отсутствуют. Результат: средой можно пользоваться как редактором.

**М2. Навигация по коду.**
Клиент LSP, реестр серверов, синхронизация документа, определение, ссылки, реализации, иерархия вызовов, символы файла и проекта, наведение, переименование, диагностика, автодополнение, панель проблем.

**М3. Терминал.**
PTY-сессии, вкладки, эмуляция экрана, изменение размера, копирование и вставка, распознавание ссылок.

**М4. Git.**
Панель состояния, диффы, индексирование, коммиты, ветки, история, blame, сетевые операции через системный `git`.

**М5. Агенты.**
Клиент ACP, панель диалога, передача контекста проекта, правки с подтверждением, запросы разрешений, история сессий, адаптер Hermes.

**М6. Доводка.**
Подключение второго агента без правки кода (проверка расширяемости), светлая тема, настройки в интерфейсе, горячие клавиши в одном реестре, устойчивость к падению внешних процессов.

## 7. Риски и допущения

| Риск | Влияние | Снижение |
|---|---|---|
| Качество собственного редактора на `egui` ниже, чем у зрелых IDE | Неудобная работа с текстом | Курсор, выделение, отмена и поиск реализуются как отдельный крейт `ide-buffer` с тестами; редактор не смешивается с отрисовкой |
| Несовместимость версий `egui` и вспомогательных крейтов (`egui_dock` 0.21 требует `egui` 0.36, `egui_commonmark` 0.25 требует `egui` 0.36) | Сборка ломается при обновлении | Версии зафиксированы; обновление — отдельная задача с прогоном интерфейсных проверок |
| Разные грамматики tree-sitter требуют разных версий рантайма | Конфликт зависимостей | Грамматики подключают `tree-sitter` только как зависимость разработки; рантайм выбирается один (0.27), совместимость проверяется тестом разбора для каждого языка |
| Языковые серверы отсутствуют в окружении или падают | Навигация недоступна | Отсутствие сервера — штатное состояние с текстовым поиском; серверы включены в `nix develop`; перезапуск из интерфейса |
| Протокол ACP меняется | Ломается интеграция агента | Клиент ACP изолирован в `ide-agents`; адаптер Hermes покрыт тестом с заглушкой процесса |
| Требования к производительности не достигаются на больших файлах | Дискомфорт при работе | Инкрементальный парс, раскраска только видимого диапазона, замеры в тестах с бюджетом времени |

**Допущения.**

1. На машине разработчика доступен `nix` с flakes.
2. Языковые серверы устанавливаются из `nixpkgs`; при их отсутствии используется текстовый режим навигации.
3. Агент Hermes предоставляет интерфейс ACP либо запускается как процесс с построчным обменом; конкретная команда задаётся в `agents.toml` и не вшивается в код.
4. Проект — один корневой каталог; поддержка многокорневых пространств не требуется в первой версии.

## 8. Критерии приёмки

**М1.**

1. `nix develop --command cargo run -p andy-ide` открывает окно с деревом проекта, областью вкладок и панелями, которые можно перетаскивать и сбрасывать.
2. Открытие файлов всех девяти языков даёт корректную подсветку; образцы для каждого языка входят в тесты.
3. Файл 10 000 строк редактируется без задержки ввода более 16 мс (замер в тесте).
4. Правка, сохранение и повторное открытие не теряют содержимое; сохранение атомарно.
5. Markdown открывается в предпросмотре с таблицами и блоками кода.
6. `Ctrl+P` находит файл по частичному имени.
7. После перезапуска восстанавливаются вкладки, курсоры и раскладка панелей.
8. `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` проходят без замечаний.

**М2.** На проекте на Rust работают: переход к определению по вызову, список мест использования, список реализаций трейта, иерархия входящих вызовов, символы файла и проекта, переименование с предпросмотром, диагностика в панели проблем. Отсутствие или падение сервера не мешает редактированию.

**М3.** Несколько сессий терминала; `vim`, `htop`, `tmux` работают; размер панели передаётся в PTY; ссылки открываются по `Ctrl+Click`.

**М4.** Панель Git отражает изменения, дифф открывается с подсветкой строк, коммит создаётся и виден в истории, переключение ветки защищено от потери правок, ошибка `push` показывается в исходном виде.

**М5.** Диалог с Hermes в панели; контекст открытого файла передаётся; правка применяется только после подтверждения и показывается диффом; разрешение на команду запрашивается явно; второй агент подключается правкой `agents.toml` без изменения кода.

**Общее.** Ни одна функция не блокирует интерфейс: во время запуска языкового сервера, git-операции или ответа агента окно продолжает перерисовываться и реагировать на ввод.
