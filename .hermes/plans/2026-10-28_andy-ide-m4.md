# М4. Git — план

Цель по ТЗ: IDE работает с git, не покидая окна: текущая ветка и её состояние в
заголовке панели, список изменённых файлов с разделением «в индексе / в рабочем
дереве», дифф по файлу, добавление в индекс и коммит, ветки, история коммитов,
отметки изменённых строк на поле редактора, `blame`. Сеть (`fetch`/`pull`/`push`) —
через системный `git`: там нужны ключи и агент, и подделывать это нельзя.

Чтение — нативно, через `gix`: индекс, объекты и рабочее дерево читаются без
запуска процесса. Так панель остаётся честной и тогда, когда `git` не установлен
или подменён обёрткой, и не платит за процесс на каждое обновление.

## Этапы

1. **Репозиторий и состояние** (`crates/ide-git/src/lib.rs`). `Repo::discover`,
   `root`, `branch`, `head_label`, `is_dirty`, `changes` — список изменений с
   видом (`Kind`) и половиной (`Area`), устойчиво отсортированный по пути и
   половине. Не-репозиторий — не ошибка, а `None`: панель так и скажет.
2. **Дифф**: текст по файлу против индекса и против `HEAD`, с номерами строк и
   подсветкой добавленных/удалённых; открывается в области редактирования только
   для чтения (не в буфер, чтобы не спутать с файлом).
3. **Коммит**: `git add` отдельного файла и `git add -u` всех; `git commit` с
   сообщением; отказ при пустом сообщении; показ ошибки хука как есть.
4. **Ветки**: список, создание, переключение; при грязном дереве — отказ с
   объяснением, а не молчаливая потеря правок.
5. **История**: коммиты с автором, датой и первой строкой сообщения; дифф коммита.
6. **Отметки на поле**: изменённые/добавленные/удалённые строки в `gutter`.
7. **`blame`** строки под кареткой — по запросу, не постоянно.
8. **Сеть**: `fetch`, `pull`, `push` системным `git`, вывод — в терминал панели.
9. **Панель в доке**: `Git` рядом с `Problems` и `Terminal`, `Alt+9` вперёд;
   при отсутствии репозитория — «не репозиторий» и кнопка `git init`.

## Сделано

- Этап 1: `Repo` на `gix` 0.90 (`default-features = false`, `status`, `sha1`);
  `changes()` собирает изменения из `gix::status` — модификация/удаление/смена
  типа/конфликт из индекс-рабочее-дерево, новые файлы из обхода каталога,
  индекс-против-`HEAD` как `Area::Staged`. `is_dirty` — родной `gix`.
  Тесты: поиск из вложенного каталога, каталог вне репозитория, грязность и её
  снятие коммитом, три вида изменений рабочего дерева, половина staged/worktree
  у одного файла, чистый репозиторий (`6` тестов).

- Этап 9, панель: `Tab::Git` в нижней полосе рядом с `Problems` и `Terminal`
  (`Alt+9`, пункт в `View`), `with_terminal` → `place_beside_problems` — старая
  раскладка получает панель, а не теряет её. `ui/git.rs` показывает ветку, число
  изменений и два раздела; строка — буква и путь от корня репозитория; клик
  открывает файл. `git::GitState` держит репозиторий по корню проекта и
  перечитывает статус не чаще раза в 1,2 с — обход дерева не бесплатен, а
  приложение должно оставаться отзывчивым. Вне репозитория — «This project is not
  a repository.», а не пустой список. Тесты `mod the_git_panel`: `Alt+9` показывает
  ветку и изменения; клик по изменению открывает файл; полу-проиндексированный
  файл виден в обоих разделах; проект без репозитория объясняет себя.
  Регрессии: снять `refresh` в панели — три теста падают; снять `follow` в `App` —
  падают все четыре.

- Этап 2, дифф: `ide-git/src/diff.rs` — `Repo::diff(path, Side)`, где `Side::Staged`
  сравнивает дерево `HEAD` с индексом, а `Side::Worktree` — индекс с файлом на
  диске. Обе стороны читаются там, где лежат (объекты в базе, файл в рабочем
  дереве): показ диффа ничего не выкладывает и не откладывает. Бинарный файл
  (`NUL` в первых 8 КБ, как у `git`) не печатается, а называется. Текст — обычный
  unified diff через `similar`, с заголовком `a/…` `b/…`. Тесты: правка против
  индекса, проиндексированная правка против `HEAD` (и пустой дифф по рабочему
  дереву), новый файл, удалённый файл, бинарный (`5` тестов). Панель `Diff` в
  нижней полосе: `Enter` в панели Git читает дифф выбранного изменения и выводит
  панель вперёд; строки окрашены (добавленные/удалённые/заголовок), прокрутка в
  обе стороны. Тест `enter_shows_the_diff_of_the_selected_change` (+`-two`,
  `+TWO` на экране). Регрессия: снять `bring_to_front(Tab::Diff)` — тест падает
  «the diff panel is not on screen».
- Один клик в панели Git только выбирает строку, двойной — открывает файл. Иначе
  клик уводил клавиатуру в редактор, и `Enter` (дифф) до панели не доходил.

## Решения

- `Kind` печатается буквой, как `git status` (`M`, `D`, `?`, `U`): панель и
  терминал говорят на одном языке.
- Порядок списка — по пути, затем по половине: панель двигает выбор по индексу,
  и список, который переставляется под рукой, — дефект.
- Пути приводятся к `String::from_utf8_lossy`: путь с невалидным UTF-8
  покажется с заменой, но не уронит панель.
- Переименования в рабочем дереве приходят двумя половинами (отслеживание
  переименований выключено): в панели это `D` + `A`, а не `R`.
