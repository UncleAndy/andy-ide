# andy-ide, этап М1 (каркас и редактирование): план реализации

> **Для исполнителя:** обязательный навык — `executing-plans` (реализация по задачам) либо
> `subagent-driven-development`. Шаги помечены чекбоксами `- [ ]`.

**Goal:** Среда, которой можно пользоваться как редактором: окно с док-панелями, дерево проекта, вкладки, текстовый буфер на rope, подсветка tree-sitter для девяти языков, атомарное сохранение, предпросмотр Markdown, quick-open, восстановление сессии.

**Architecture:** Рабочее пространство Cargo из восьми крейтов. Логика (проект, буфер, подсветка) живёт в библиотечных крейтах без `egui`; единственный крейт с интерфейсом — `andy-ide`, он подписан на события фоновых задач и разбирает их в начале кадра. Подсветка считает диапазоны токенов только для видимых строк.

**Tech Stack:** Rust edition 2024, `egui`/`eframe` 0.36.2, `egui_dock` 0.21.1, `egui_commonmark` 0.25.0, `ropey` 1.6.1, `tree-sitter` 0.27.1, `nucleo` 0.5, `notify` 8.2.1, `ignore` 0.4.34, `tokio` 1.54.

**Spec:** `docs/TZ_andy_ide_v0.1.md` (разделы 3.1–3.3, 4, 5; этап М1 в разделе 6)

## Global Constraints

- Rust edition 2024, toolchain ≥ 1.95 (`egui_dock` 0.21.1 требует 1.95).
- Версии крейтов зафиксированы: `egui`/`eframe` `0.36.2`, `egui_dock` `0.21.1`, `egui_commonmark` `0.25.0`, `ropey` `1.6.1`, `tree-sitter` `0.27.1`. `egui_dock` 0.21 и `egui_commonmark` 0.25 требуют ровно `egui` 0.36 — обновление любого из трёх отдельной задачей.
- Грамматики tree-sitter объявляют `tree-sitter` только как зависимость разработки (`kind: dev`), поэтому конфликта версий нет; рантайм один — 0.27.1.
- `cargo clippy --all-targets -- -D warnings` и `cargo fmt --check` обязательны в каждой задаче.
- Сборка только через `nix develop --command ...`; `CARGO_TARGET_DIR=$HOME/.cache/andy-ide-target`, каталог `target/` в репозитории не создаётся.
- Библиотечные крейты не зависят от `egui`/`eframe`; `unwrap`/`expect` в библиотеках запрещены.
- Строки файлов читаются как UTF-8; файл в не-UTF-8 считается ошибкой с понятным сообщением, не паникой.
- `eframe` 0.36: трейт `App` требует `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`; `egui::CentralPanel::show` принимает `&mut Ui`; метода `update(&mut self, ctx, frame)` больше нет. Остальные примеры из старых источников использовать нельзя без сверки с `docs.rs/eframe/0.36.2`.
- Все текстовые файлы после записи очищаются от `\r` и `\x1b` (`tr -d '\r\033'`), иначе ломается сборка.
- Коммит после каждой задачи; `git push` не выполняется.

## Review Focus

1. Файл в не-UTF-8 или с `\r\n` — открывается без паники, переводы строк не съезжают, сохранение не превращает `\r\n` в `\n`.
2. Пустой файл и файл из одной строки без завершающего перевода строки — курсор, нумерация строк и подсветка работают на границах.
3. Каталог без прав на чтение или удалённый во время работы — дерево показывает ошибку на узле, а не падает и не зависает.
4. Вставка большого фрагмента (1000 строк) и отмена после неё — отмена возвращает состояние целиком, подсветка не пересчитывает весь файл.
5. Файл изменён на диске при наличии несохранённых правок — правки не теряются молча, показывается выбор.

**Уточнения, выявленные реализацией (читать до начала задачи):**

1. **Запросы грамматик неполны у трёх языков.** `tree-sitter-typescript` поставляет только TypeScript-специфичную половину (в nvim-раскладке ожидается `inherits: javascript`, а JS-запрос упоминает JSX-узлы, которых в TS-грамматике нет), `tree-sitter-cpp` — только C++-дополнение к C, `tree-sitter-md` — два запроса, блок и inline. Поэтому: для TypeScript/TSX в репозитории лежат `queries/typescript.scm` и `queries/tsx_extra.scm` (подключаются `include_str!`), для C++ запрос собирается во время выполнения как `C-запрос + "\n" + C++-запрос` — отсюда `highlights_query(self) -> Cow<'static, str>`, а не `&'static str`.
2. **Две грамматики TypeScript + JavaScript — это три крейта.** `tree-sitter-typescript` даёт `LANGUAGE_TYPESCRIPT` и `LANGUAGE_TSX`, но не JavaScript: для JS нужен отдельный крейт `tree-sitter-javascript` (в плане он отсутствовал). Константы запросов называются по-разному: `HIGHLIGHTS_QUERY` у rust/python/typescript/json/toml/go, `HIGHLIGHT_QUERY` у javascript/bash/c/cpp, `HIGHLIGHT_QUERY_BLOCK` у markdown.
3. **Числовые литералы Rust приходят как `@constant.builtin`.** Чтобы `TokenKind::Number` действительно означал число, вид уточняется по имени узла (`refine_kind`).
4. **`QueryCursor::matches` — не `Iterator`, а `StreamingIterator`** (крейт `streaming-iterator` 0.1), поле `QueryMatch::captures` приватное, нужен метод `captures()`.
5. **Тест инкрементальной правки в плане содержал ошибку в арифметике:** `new_end_byte` равен `byte_start + len(inserted)`, то есть 29, а не 20. В реализации тест считает эту величину из `inserted.len()`; метод для доступа к тексту называется `Highlighter::text()`, а не `text_for_test()`.

```rust
use ide_core::restore::restore_tabs;
use ide_core::{Session, TabState};
use std::path::Path;

fn tab(p: &str) -> TabState { TabState { path: p.into(), cursor_line: 0, cursor_col: 0 } }

#[test]
fn missing_files_are_dropped_on_restore() {
    let s = Session { tabs: vec![tab("/a.rs"), tab("/b.rs"), tab("/c.rs")], active: Some(1), layout: None };
    let restored = restore_tabs(&s, |p| p != Path::new("/b.rs"));
    assert_eq!(restored.len(), 2);
    assert_eq!(restored[0].path.to_string_lossy(), "/a.rs");
}

#[test]
fn restore_of_empty_session_is_empty() {
    let s = Session { tabs: vec![], active: None, layout: None };
    assert!(restore_tabs(&s, |_| true).is_empty());
}
```
