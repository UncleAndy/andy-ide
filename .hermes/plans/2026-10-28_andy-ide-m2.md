# andy-ide, этап М2 (навигация через языковой сервер): план и состояние

**Goal:** Переход к определению, поиск ссылок, символы файла и проекта, подсказка типа — всё через настоящий LSP-сервер, без блокировки интерфейса, с работающим редактором при упавшем или отсутствующем сервере.

**Spec:** `docs/TZ_andy_ide_v0.1.md`, раздел 3.4 и этап М2.

**Состояние на 2026-10-28:** задачи 1–2 закрыты (`27be759`, `2480af0`), 219 тестов зелёные, `clippy -D warnings` и `fmt --check` чисты.

## Отклонения от ТЗ, принятые сознательно

1. **Транспорт вместо `async-lsp`/`tokio`.** Приложение — синхронный кадровый цикл, асинхронного рантайма в нём нет; тащить `tokio` только ради клиента значит держать два способа ожидания в одном процессе. Сделано: транспорт на потоках (`Content-Length` + JSON-RPC), отдельный поток чтения, у каждого запроса таймаут, запросы к серверу идут в рабочий поток с очередью. Типы сообщений — из `lsp-types` 0.97, протокол не изобретается.
2. **Полная синхронизация документа.** Изменение без `range` по спецификации означает «весь документ», это принимают и серверы с инкрементальной синхронизацией; версия документа растёт.

## Сделано

- [x] **Задача 1: транспорт и сессия** (`crates/ide-lsp`). `framing` (заголовок, граница тела), `rpc` (запрос/уведомление/ответ, коды ошибок), `client` (`ServerProcess` + `LspSession`: запуск процесса, `initialize` с `rootUri` и workspace folders, `initialized`, `didOpen`/`didChange`/`didClose`, `definition`, `references`, `hover`, `documentSymbol`, выдача диагностик), `uri` (percent-encoding путей, кириллица и пробелы), `position` (UTF-16 ↔ байты, CRLF, эмодзи), `registry` (таблица серверов: rust-analyzer, pyright, typescript-language-server; отсутствующий сервер — сообщение, не паника).
- [x] Поток чтения отдаёт ответы ожидающим, уведомления — в очередь; stderr сервера вычитывается (иначе сервер встаёт на полном канале); запросы сервера к клиенту отвечаются `null`, чтобы сервер не ждал.
- [x] **Задача 2: F12 и панель проблем** (`crates/andy-ide`). `lsp` — рабочий поток с очередью задач (`Open`/`Change`/`Close`/`Definition`), `LanguageService::poll` — разбор ответов в начале кадра. Сервер поднимается при первом запросе, а не при открытии проекта; открытые документы объявляются в этот момент. `F12` → определение под каретой → открытие файла на объявлении; ответ вне проекта — сообщение. Закрытие вкладки → `didClose`. Панель Problems: строка на диагностику, клик ведёт на строку.
- [x] Холодный сервер отвечает «ничего», пока не загрузил проект: пустой ответ до первого успеха переспрашивается с растущей паузой (250/500/1000/2000 мс) в рабочем потоке.
