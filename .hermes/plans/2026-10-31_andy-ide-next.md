## 1. Уведомление — только когда на панель не смотрят

**Сделано (коммит `7ab0815`), 31.10.** Правило — `should_tell(Looking { focused, panel_in_front }) =
!(focused && panel_in_front)` в `notify.rs`; обстоятельства пишет `App::draw` в `AgentState::looking`,
читает поток агента через `Telling { desk, looking }`; решитель и отправитель — `tell_the_desk`.
Проверки: таблица правила, кадр с клавиатурой и без (`app.rs`), сам отправитель с `Written`-поверхностью
(`agent.rs`) — у каждой свой контроль. Andy подтвердил: предохранитель снимался «только на время
отладки», так что это не пересмотр решения, а его возврат. Ниже — исходная постановка, оставлена для
истории.

**Смысл правила (предложение, требует подтверждения Andy):** извещение уходит, **кроме** случая, когда
человек смотрит на панель агента — то есть `!(focused && panel_in_front)`. Это возврат предохранителя,
убранного 31.10 по слову Andy («убрать предохранители… показывать всегда»), поэтому в задаче № 1
исполнитель обязан переспросить формулировку, а не выбирать её сам.

**Почему это не «вернуть как было»:** отправка теперь в потоке агента, который о том, где окно, не знает —
в отличие от панели, откуда отправка шла раньше. Значит, обстоятельства нужно **передать в поток**.

**Файлы:**

- `crates/andy-ide/src/notify.rs` — новое `Looking { focused: bool, panel_in_front: bool }` и
  `should_tell(&Looking) -> bool` (одно место, где живёт правило);
- `crates/andy-ide/src/agent.rs` — у `AgentState` поле `looking: Arc<Mutex<Looking>>` (значение по
  умолчанию — «не смотрят», т.е. сообщать: окно, не нарисовавшее ни кадра, не может утверждать обратное);
  `work(..)` получает этот `Arc` и спрашивает `should_tell` в момент события; в журнал рядом с отправкой
  пишутся `focused`, `panel_in_front` и `told=true|false` (строка «the panel wants the person» была и
  нужна: без неё «не сообщили» неотличимо от «агент не просил»);
- `crates/andy-ide/src/app.rs` — `App::draw` пишет `looking` каждый кадр (рядом с передачей `notifier`) и
  возвращается `panel_in_front()` (удалён в `bc536d4`), `pub(crate)`;
- `crates/andy-ide/src/gui_tests.rs` — проверки.

## 2. Протокол ACP — на официальном SDK

**Цель:** клиентская сторона ACP перестаёт быть своей реализацией и становится SDK, свои остаются только
поведение панели и журнал провода.

**Что известно о SDK (проверено 31.10):**

- `agent-client-protocol` **3.6.0** (crates.io, обновлён 28.10.2026; репозиторий
  `github.com/agentclientprotocol/rust-sdk`, Apache-2.0) — рантайм клиента и агента;
- `agent-client-protocol-schema` **1.14.0** — типы сообщений ACP (низкий уровень);
- **стабильная версия протокола — `1`**; v2 — за флагами `unstable_protocol_v2`;
- флаги: `process` (запуск агента: `async-process`, `async-io`, `rustix`, `shell-words`), `stdio`
  (`blocking`); зависимости рантайма — `futures`, `futures-concurrency`, `serde`, `uuid`, `tracing`;
  **`tokio` в рантайм-зависимостях нет** (он только в dev-зависимостях SDK) — то есть проект, у которого
  tokio отсутствует сознательно, может взять SDK с `process`, а синхронные потоки соединить с `futures`
  через `blocking`/простой исполнитель;
- примеры в SDK: `yolo_one_shot_client` (нужен `process`), `simple_agent`, а также примеры v2.

**Текущее состояние (что заменяется):**

  `Setup`, `Usage`, `Commands`, `Sessions`, `Thinking`, `Plan`, `Other`, `Closed`, `Failed`), а также

`Responder` в карте по нашему номеру вопроса: ответ приходит из другого потока позже.

**Найдено и важно для продолжения:** цикл приказов **не должен ждать ход**. Первая версия ждала
`PromptRequest` прямо в цикле, и ответ человека (который приходит *во время* хода) не мог быть обработан —
взаимная блокировка, которую видели две проверки, падая по сроку. Теперь ход уходит задачей
(`cx.spawn`), а ходы друг за другом держит `futures::lock::Mutex`. Это же место — где появится `cancel`:
`session/cancel` отправляется во время хода, значит и он должен идти из цикла, а не из задачи хода.

**Осталось:** `list_sessions`, `cancel`, `set_model`/`set_mode`/`set_option`, `begin`/`load_into` как

открывается заново, шаги запуска прежние, обещания о себе в рукопожатии и в `_meta`, сторож смерти процесса
(соединение само её не замечает — панель не узнавала о падении), и панель больше не заявляет «resumed»
вслепую.

Осталось: убрать из `protocol.rs` мёртвые формы прежнего провода с их проверками.
### Остатки прежнего протокола убраны — 2026-11-01

Из `protocol.rs` снято 22 мёртвых объявления прежнего своего провода (со своими `impl` и проверками):
`Message`, `Update`, сборщики доводов, ответы на вопросы, счётчики контекста, старые возможности клиента.
Осталось 990 строк живых разборщиков. Три правила из удалённых проверок перенесены в `sdk_session.rs`: вопрос
со свободным ответом, вопрос с несколькими ответами, отказ человека.

Так шаг 3 закрыт: реализация одна (SDK), панель не менялась, мёртвых форм не осталось.
