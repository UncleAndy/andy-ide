## 1. Уведомление — только когда на панель не смотрят

**Сделано (коммит `7ab0815`), 31.10.** Правило — `should_tell(Looking { focused, panel_in_front }) =
!(focused && panel_in_front)` в `notify.rs`; обстоятельства пишет `App::draw` в `AgentState::looking`,
читает поток агента через `Telling { desk, looking }`; решитель и отправитель — `tell_the_desk`.
Проверки: таблица правила, кадр с клавиатурой и без (`app.rs`), сам отправитель с `Written`-поверхностью
(`agent.rs`) — у каждой свой контроль. Andy подтвердил: предохранитель снимался «только на время
отладки», так что это не пересмотр решения, а его возврат. Ниже — исходная постановка, оставлена для
истории.

**Смысл правила (предложение, требует подтверждения Andy):** извещение уходит, **кроме** случая, когда
человек смотрит на панель агента — то есть `!(focused && panel_in_front)`. Это возврат предохранителя,
убранного 31.10 по слову Andy («убрать предохранители… показывать всегда»), поэтому в задаче № 1
исполнитель обязан переспросить формулировку, а не выбирать её сам.

**Почему это не «вернуть как было»:** отправка теперь в потоке агента, который о том, где окно, не знает —
в отличие от панели, откуда отправка шла раньше. Значит, обстоятельства нужно **передать в поток**.

**Файлы:**

- `crates/andy-ide/src/notify.rs` — новое `Looking { focused: bool, panel_in_front: bool }` и
  `should_tell(&Looking) -> bool` (одно место, где живёт правило);
- `crates/andy-ide/src/agent.rs` — у `AgentState` поле `looking: Arc<Mutex<Looking>>` (значение по
  умолчанию — «не смотрят», т.е. сообщать: окно, не нарисовавшее ни кадра, не может утверждать обратное);
  `work(..)` получает этот `Arc` и спрашивает `should_tell` в момент события; в журнал рядом с отправкой
  пишутся `focused`, `panel_in_front` и `told=true|false` (строка «the panel wants the person» была и
  нужна: без неё «не сообщили» неотличимо от «агент не просил»);
- `crates/andy-ide/src/app.rs` — `App::draw` пишет `looking` каждый кадр (рядом с передачей `notifier`) и
  возвращается `panel_in_front()` (удалён в `bc536d4`), `pub(crate)`;
- `crates/andy-ide/src/gui_tests.rs` — проверки.

**Шаги (TDD, по 2–5 минут):**

1. Тест: таблица `should_tell` на четыре сочетания `focused × panel_in_front` — вручную нарисованный
   ожидаемый ответ, не вычисленный тем же выражением. Запустить, убедиться, что падает.
2. Реализация `Looking` + `should_tell`; тест зелёный. **Контроль:** перевернуть правило (`!should_tell`)
   — таблица обязана упасть; вернуть.
3. Тест решения в потоке: при «смотрят» `work` не зовёт рабочий стол, при «не смотрят» — зовёт. Юнитом
   это проверяется на самой функции решения, сквозным — проверкой ниже (поверхность `Written`).
4. `gui_tests`: панель агента впереди и окно в фокусе → `written.shown()` пуст; панель за вкладкой
   терминала → одна запись. Для фокуса вернуть ручной кадр с `RawInput.focused = true` (прежний
   `draw_frame_with_focus` был удалён вместе с тестами панели).
5. Приспособить `a_question_reaches_the_desk_without_the_window_being_drawn`: без кадров `looking`
   остаётся «не смотрят» — проверка обязана по-прежнему проходить (и это её смысл: кадр не нужен).
6. Ворота: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
   `cargo test -p andy-ide --bin andy-ide`. Затем проба у Andy: сидя в панели — тишина, с другого
   рабочего пространства — извещение.

**Риск:** правило может «съесть» нужное извещение (панель впереди, но человек отошёл от стола). Второй
вариант, если это окажется так: смотреть только на `focused` (без `panel_in_front`).

## 2. Протокол ACP — на официальном SDK

**Цель:** клиентская сторона ACP перестаёт быть своей реализацией и становится SDK, свои остаются только
поведение панели и журнал провода.

**Что известно о SDK (проверено 31.10):**

- `agent-client-protocol` **3.6.0** (crates.io, обновлён 28.10.2026; репозиторий
  `github.com/agentclientprotocol/rust-sdk`, Apache-2.0) — рантайм клиента и агента;
- `agent-client-protocol-schema` **1.14.0** — типы сообщений ACP (низкий уровень);
- **стабильная версия протокола — `1`**; v2 — за флагами `unstable_protocol_v2`;
- флаги: `process` (запуск агента: `async-process`, `async-io`, `rustix`, `shell-words`), `stdio`
  (`blocking`); зависимости рантайма — `futures`, `futures-concurrency`, `serde`, `uuid`, `tracing`;
  **`tokio` в рантайм-зависимостях нет** (он только в dev-зависимостях SDK) — то есть проект, у которого
  tokio отсутствует сознательно, может взять SDK с `process`, а синхронные потоки соединить с `futures`
  через `blocking`/простой исполнитель;
- примеры в SDK: `yolo_one_shot_client` (нужен `process`), `simple_agent`, а также примеры v2.

**Текущее состояние (что заменяется):**

- `crates/ide-agents/src/protocol.rs` — свои типы сообщений;
- `crates/ide-agents/src/session.rs` — свои трубы, разбор, `Event` (`Permission`, `Choice`, `Finished`,
  `Setup`, `Usage`, `Commands`, `Sessions`, `Thinking`, `Plan`, `Other`, `Closed`, `Failed`), а также
  запись журнала провода;
- `crates/ide-agents/src/wire.rs` — сырой журнал (`~/.local/state/andy-ide/acp-wire.log`), который обязан
  сохраниться: он единственное, что отличает «агент молчал» от «панель не нарисовала»;
- `crates/andy-ide/src/agent.rs` — потребитель (`Event as AgentEvent`), менять его **не нужно**, если
  сохранить поверхность `Session`.

**Шаги:**

1. **Проба (spike, отдельный бинарник, вне панели).** `crates/ide-agents/examples/acp_probe.rs`: поднять
   одного агента через SDK (`process`) и печатать каждое событие. Вопрос пробы один: приходят ли те же
   события, что мы разбираем сейчас, на нашем агенте (Hermes через ACP). Результат — вывод пробы в задаче.
2. **Таблица соответствия** (обязательный артефакт, `docs/acp-sdk-mapping.md`): каждый вариант нашего
   `Event` против типа SDK — «есть», «нет в SDK», «лишнее у нас». Пока в таблице есть «нет в SDK»,
   свой слой не удаляется.
3. **Журнал провода.** Обернуть транспорт SDK так, чтобы `wire.rs` видел обе стороны по-прежнему
   (байтовая обёртка `Read`/`Write`, либо хук сырых сообщений SDK, если он есть). Если ни того, ни
   другого — запасной путь: взять из SDK только `agent-client-protocol-schema` (типы), свой транспорт
   оставить; это и записать в таблицу как решение.
4. **Замена под существующей поверхностью:** `Session::start_with`, `next_event`, `answer_permission`,
   `answer_choice`, `list_sessions`, `cancel`, `set_model`, `set_mode`, `set_option`, `begin`,

   проверки панели.
5. **Зависимость и MSRV:** `agent-client-protocol = "3.6"` в `crates/ide-agents/Cargo.toml`; сверить
   `rust-version` SDK с нашим набором (у проекта 1.95) — до первой строки кода.
6. **Удаление своего слоя** — по одному варианту за коммит, каждый со своими воротами; последним уходит
   `protocol.rs`.
